# Модель Типов

Этот раздел описывает общие правила типов в сценариях. Детали отдельных функций находятся в [functions](functions/index.md).

## Доменные Типы

Loader работает с доменными типами:

| Тип | Назначение |
| --- | --- |
| `Text` | текст |
| `Integer` | целое число |
| `Number` | десятичное/вещественное число |
| `Boolean` | логическое значение |
| `Date` | дата/дата-время |
| `Time` | время |
| `Unknown` | тип не определен |

Физический тип в ClickHouse может отличаться от доменного. Например `Time` может физически храниться как `DateTime`, но следующий `LOAD` видит доменный `Time`.

## Nullability

У каждого поля есть признак nullable.

Поле становится nullable, если источник может вернуть `null` или выражение может вернуть `null`.

Примеры:

```ts
LOAD
  ''.EmptyIsNull() AS maybe_empty,
  Date('bad') AS maybe_date
FROM Numbers(1);
```

Оба выражения могут дать `null`.

## Поведение Null В Функциях

Обычно функции распространяют `null`: если значимый аргумент равен `null`, результат тоже `null`.

Пример:

```ts
LOAD
  null + 1 AS value
FROM Numbers(1);
```

Исключения описываются в документации конкретной функции. Например условные функции могут выбирать не-null ветку, а проверки `IsNull`/`NotNull` специально работают с `null`.

## Неявное Приведение

Resolver может добавить неявное приведение, если функция или оператор поддерживает аргумент другого, но совместимого типа.

Пример:

```ts
LOAD
  amount + 1 AS amount_plus_one
FROM source;
```

Если `amount` имеет тип `Number`, целое `1` может быть приведено к числовому типу выражения.

Не все сочетания типов приводятся автоматически. Если типы несовместимы, лучше сделать явное преобразование:

```ts
LOAD
  amount_text.Num() AS amount
FROM source;
```

## Явные Преобразования

Основные функции преобразования:

- `Text(value)`
- `Int(value)`
- `Num(value)`
- `Date(value)`
- `Time(value)`

Методная форма эквивалентна обычной:

```ts
Int(id)
id.Int()
```
